# v1.0.0 installation optimization Raspberry Pi checklist

Use this checklist on a Raspberry Pi 5 after merging the installer and
documentation optimization. It validates the new setup path while rechecking
that the existing robot functions remain unchanged.

Record the date, commit, Raspberry Pi OS version, operator, and pass/fail result
for each section. Stop at the first unsafe or unexplained result.

## Preconditions

- Disconnect or raise both wheels so they cannot drive the robot.
- Keep an operator ready to remove power.
- Confirm I2C and SPI are enabled in `raspi-config`.
- Obtain consent before camera or microphone testing.
- Back up existing `~/.config/pi5*`, `~/.config/ninjarobot_pi5`, and
  `~/.local/share/ninjarobot_pi5` data when validating an existing robot.
- Do not delete the working installation until its current configuration and
  memory have been backed up and the clean clone is ready.

## Safe smoke tests

1. Clone the repository and run `./install.sh --dry-run`.
   Expected: it lists the pinned packages/tools and explicitly says it will not
   start the Agent, pull a model, capture media, move hardware, or reboot.
2. Run `./install.sh`, type `INSTALL`, and allow it to finish.
   Expected: packages, uv, Ollama, whisper.cpp, private directories, locked
   dependencies, camera bridge, and provenance all pass; no robot device opens.
3. Reboot once, return to the clone, and run `./install.sh --check`.
   Expected: the pinned versions, Ollama service, OS packages, whisper assets,
   Picamera2 bridge, PWM block, private directories, environment, and driver
   provenance pass.
4. Rerun `./install.sh`.
   Expected: healthy work is reused, the managed PWM block is not duplicated,
   and no private configuration is overwritten.
5. Run `git status --short`.
   Expected: initialization has not created checkout-root runtime JSON or media.

Rollback: restore the timestamped
`/boot/firmware/config.txt.ninjarobot-backup-*` file with `sudo cp`, then reboot.
Do not restore a backup until its GPIO and audio settings have been reviewed.

## Device communication tests

Stop NinjaRobotAgent before opening a standalone device tool.

1. Open `pi5buzzer buzzer-tool`, choose **Init**, and press Enter.
   Expected: GPIO27 is displayed, a short test tone plays, and then silence.
2. Open `pi5disp display-tool`, choose **Init**, and press Enter at every prompt.
   Expected: GPIO4/GPIO5/GPIO6, rotation 90, and brightness 75 are saved; text,
   brightness, and clear operations work.
3. Open `pi5vl53l0x sensor-tool` and take repeated readings.
   Expected: the sensor responds at I2C address `0x29`; valid targets change the
   distance and the documented out-of-range sentinel is handled safely.
4. Open `pi5camera camera-tool`, accept the fixed-focus defaults, and run doctor.
   Expected: the system-Python bridge reports ready. Capture only with consent,
   then delete unneeded test media.
5. Open `pi5mic mic-tool`, select the USB microphone, and accept detected
   whisper/wake defaults. Run doctor and one consented transcription.
   Expected: local speech is transcribed and temporary command audio is removed.

Rollback: exit the tool, stop the owning process, disconnect robot power before
changing wiring, and restore the relevant backed-up JSON if configuration is
incorrect.

## Actuator-moving tests

> [!CAUTION]
> Keep both wheels raised for this entire section.

1. Open `pi5servo servo-tool`, confirm GPIO12 and GPIO13 calibration, and test
   each wheel at its lowest practical speed in both directions.
   Expected: each wheel moves as selected and returns to its calibrated neutral
   without creep.
2. Open `ninjarobot-ide-tool`, verify hardware status, run a short Greeting,
   trigger Emergency Stop, and then use Resume Robot Movement.
   Expected: motion and sound stop, the stop icon appears, resume restores the
   display, and the robot returns to Idle.
3. Start NinjaRobotAgent, arm AI motion explicitly, and request one bounded
   movement behavior.
   Expected: the IDE executes it once, returns the result, and all outputs stop.

Rollback: use Emergency Stop, remove robot power if output continues, and do
not resume until logs and calibration have been reviewed.

## Existing-function regression

- Verify terminal chat, local web access, model switching, shared long-term
  memory, built-in robot MCP tools, optional Tavily configuration, profile face
  enrollment, behavior recording, and Emergency Stop recovery.
- Enable voice input, say **Hey Ninja**, speak a short command, and verify early
  silence completion; then disable voice input.
- If ngrok is configured, verify pairing QR, browser connection, Greeting, and
  return to Idle. If ngrok is unavailable during deployed startup, verify the
  local URL QR fallback.

Expected: behavior matches the v1.0.0 Phase 8 acceptance records, with no
checkout-root settings and no memory mixing between users.

## Power-risk tests

Run these tests last and only with the Geekworm X1208 assembled and powered as
documented in the Installation Guide.

1. Through **Startup Agent deployment**, install and enable automatic startup,
   then reboot.
   Expected: the Agent starts once and displays the remote QR or documented
   local fallback without manual login.
2. Connect an authenticated browser and confirm the Web power-off dialog.
   Expected: the Agent stops, Raspberry Pi OS powers off, and the X1208 removes
   the Pi 5 V rail. The Pi must not reboot.

Rollback: if startup fails, use **Disable and stop automatic startup Agent** and
inspect the documented service log. If shutdown completes but power remains,
disconnect input power safely and recheck X1208 pogo-pin, EEPROM, and
`power_off_on_halt` setup before repeating.

## Pass criteria

Pass only when every applicable expected result is observed and no unexplained
service, hardware-owner, safety, configuration, privacy, boot, or power error
remains. Keep this completed checklist with the release validation evidence.
