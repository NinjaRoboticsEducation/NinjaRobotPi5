## Architecture and Phase 5–7 parity

- All hardware access remains inside `ninjarobot_pi5_ide`; the agent adds no
  direct `pi5*` import or second microphone/display/motion owner.
- Existing terminal/web chat, provider switching, MCP, skills, behavior
  creation/catalog, stop/resume, camera grants, motion arming, face identity,
  user selection, and user-scoped persistent memory remain covered by the full
  regression suite.
- Phase 8 changes are additive and default disabled. Existing manual startup
  keeps the historical immediate Greeting/Idle flow when onboarding is off.
- Enabling boot preserves all Phase 7 user/profile/face/memory/conversation/
  behavior/model/calibration/safety/secret paths and schemas.

## Privacy and remote-threat result

- Wake inference and transcription are local, raw background/command audio is
  not retained, and v1.0.0 has no TTS.
- Voice motion shares existing explicit arm state and revocation paths.
- ngrok performs no unattended download; its token and internal transport,
  pairing, and session secrets are private and redacted.
- Local onboarding and remote use require one-use physical-presence pairing.
  Host/Origin/transport-marker checks, secure cookies, expiry, rotation,
  endpoint replacement, and exclusive leases reject anonymous assets,
  WebSockets, robot controls, and power-off.
- Power-off is deterministic, paired, lease-bound, twice confirmed, replay
  protected, and limited to a fixed root-owned helper after cleanup.

No unresolved anonymous remote-control or software safety-critical issue was
identified by the test/audit pass.

## Packaging, license, and provenance

- The root MIT license, direct-dependency notices, exact transitive `uv.lock`,
  driver license records, wake-model approval/hash, and three offline runtime
  asset hashes are present.
- Built agent data includes all four locale dictionaries and systemd/helper/
  sudoers templates. Built IDE data includes the approved custom ONNX model and
  openWakeWord feature/VAD assets.
- The nested `NinjaClawBot/` repository is not imported, copied, or packaged.

## Required Raspberry Pi acceptance

Complete and sign the Phase 8.2 voice, 8.3 ngrok, 8.4 UI/power, 8.5 QR/Greeting,
and 8.6 boot/deployment checklists. These cover microphone soak and wake false
positives, live ngrok behavior, four-browser-locale accessibility, display QR
readability, raised-wheel Greeting and armed voice motion, boot/crash/clean-stop
lifecycle, privilege denial, orderly power-off, thermal/storage integrity, and
backup/rollback/uninstall.

Until those pass, the residual hardware and external-service risks in the
[support matrix](../architecture/v1.0.0-support-matrix.md) remain open and the
repository must be described as a release candidate.
